## What you are doing
You will rate 100 short search queries. The two annotators, **A1** and **A2**, work independently.

Each row of your sheet shows:
- **dataset** and **domain**: the service the query is for;
- **query**: the query to rate;
- **passage**: a help-page or answer passage from that service's collection;
- **neighbour_1 … neighbour_5**: five queries that real users of the same service typed for similar needs, shown in random order. Use them as a reference for how real users of this service type. They are not the query you are rating.

**You are not told whether a query was typed by a real person or generated by a model, and you never see any model ratings.** Items appear in a random order, and the item ID says nothing about where an item came from. Rate what you see.

Imagine the service's help-search box on a phone. Ask yourself: *how likely is it that a real user typed exactly this?*

**Domain** (under A2, every item is from this dataset):
- **fiqa:** personal finance questions from StackExchange and Reddit users.

## Scales (1–5; the same anchors the judge uses, spec B.4)
| Column | Question | 5 | 3 | 1 |
|---|---|---|---|---|
| **F**: Fidelity | Does the passage contain what this person needs to act on? | fully answers it | partly | does not |
| **H**: Human-likeness | Do length, wording, register, abbreviations, typos and detail look like what real users type? The five neighbours show how real users of this service type. | like a real user query | plausible but noticeably more formal or complete | reads like an exam question, a documentation heading or a chatbot prompt |
| **S**: Natural specificity | Does it use only words and details a user would know **before** reading the passage? | only pre-document knowledge | one passage-specific term or detail | relies on passage-only terminology, exact figures, conditions or steps |
| **P**: Need plausibility | Would many real users have this need? | a common need | occasional | an obscure detail only a document reader would ask |
| **C**: Code-mix naturalness | **Only if the query is not pure English**; otherwise leave the cell blank | mixing and spelling look like natural Indian typing | understandable but slightly stiff | mechanically swapped words, formal or Sanskritised transliteration, unnatural grammar |
| **overall**: Overall realism | How likely is it that a real user typed exactly this? | very likely | unsure | very unlikely |

Use whole numbers 1–5, and use 2 and 4 for in-between cases. Every row needs F, H, S, P and overall. C stays blank for pure-English queries.

## Rules (spec Appendix C)
- **Typos and abbreviations** are neither good nor bad in themselves. Judge them against how real users type.
- **Hinglish:** treat spelling variation (*nahi / nahin / nai*) as natural. Penalise pure dictionary transliteration of formal Hindi that nobody types in chats.
- **Fidelity:** read the passage. A query is answerable if the passage contains what the person needs to act on.
- **Rate each column independently.** A query can be very human-like (H = 5) yet unanswerable by the passage (F = 1).
- **Neighbours are a reference, not a template.** A query does not need to resemble any single neighbour to be realistic. Also, do not mark a query down just because it is about a different topic from its neighbours.
- **Do not edit** the item_id, dataset, domain, query, passage or neighbour columns. The import step rejects a sheet in which any of them changed.

## The spreadsheet (D-050; no Label Studio)
The files are in `data/calibration/sheets/` and are UTF-8 CSV that opens in Excel or LibreOffice. Save it back as CSV (UTF-8).

| File | Who fills it | What |
|---|---|---|
| `practice.csv` | A1 and A2 **together** | The 20 practice items |
| `raw_r1_A1.csv` | **A1 only** | All 100 items; your own ratings |
| `raw_r1_A2.csv` | **A2 only** | All 100 items; your own ratings |
| `adjudication_r1.csv` | both, **after** both raw sheets are complete | Only `<dim>_settled` where `<dim>_discuss` = 1, plus `adjudication_notes` |

- **Columns you fill:** F, H, S, P, C, overall, `flag_unclear` (write `1` if the item is unclear) and `notes`. `annotator_id` is already filled in.
- **Raw sheets are never edited after they are handed in.** Adjudication happens in a separate file, and the final labels are computed from it (`final_labels_r1.csv`). Nobody types final labels by hand.
- The **key file** (`data/calibration/key.csv`) links item IDs to their origin. **Annotators do not open it** until the analysis stage.

## Process (prereg §4.3–4.4)
1. **Practice:** rate the 20 practice items **together** in `practice.csv`, and discuss them to align your reading of the anchors. They are not among the 100 and are not used in any analysis.
2. **Main set:** each annotator rates all 100 items **independently** in their own raw sheet. Flag unclear items, but **do not discuss them until both have finished**. Do not compare sheets.
3. **Import:** `ha calib import --round 1` checks both sheets (IDs, text unchanged, values 1–5, required cells filled). It then writes `adjudication_r1.csv`, which puts both ratings side by side with the mean and difference. Items are flagged `<dim>_discuss` = 1 when the two ratings differ by 2 or more, or when only one annotator rated C.
4. **Agreement:** quadratic-weighted Cohen's κ per dimension. If κ < 0.5 on any dimension, these guidelines are revised **once** and 40 `cal-dev` items are re-annotated (round 2 sheets). Both κ values are reported.
5. **Adjudication:** discuss each flagged item and enter the agreed value in `<dim>_settled`. For C you can enter `NA` if you agree the query is pure English. Leave every unflagged cell blank.
6. **Human reference:** `ha calib finalize --round 1` writes `final_labels_r1.csv`. Each value is the mean of the two ratings, or the settled value for flagged items (prereg §4.4). It refuses to run while any flagged item is unsettled.

## How the items were prepared (for the paper; annotators do not need this to rate)
- **Passages:**
  - For generated items, the passage is the one the query was generated from.
  - For real items, it is a real relevance-judged (qrels) passage: among the item's qrels with the highest grade, the pids are sorted and one is chosen by a fixed hash of the item (D-050).
  - No passage is written, edited or chosen by hand. An item with no qrels passage stays pending.
- **Neighbours:**
  - These come from the same retrieval procedure the judge uses, but over the real-query reference pool with all real calibration items removed (30 under A2). This ensures that a real calibration item never appears as a neighbour of another item, which would reveal that it is real.
  - This is a display rule for annotators only. The judge's own neighbours are unchanged.
